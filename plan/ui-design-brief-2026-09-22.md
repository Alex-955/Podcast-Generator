## 2. 用户目标与取舍

本轮只解决：粘贴文章 → 知道处理到哪一步 → 失败时知道如何继续 → 成功后在本地 Web 收听。

明确约束：
- 桌面 Web 主流程优先，保持基本窄屏可用即可；不做独立移动端/PWA/跨设备。
- 不把导出、分享、复杂剧本微调作为主操作；已有能力可以作为次级入口，不擅自删掉。
- 用户要真实进度，不要匀速假进度或一直转圈。
- 商业 TTS 尚未选定。设置可以预留解释，但不能把任意 Provider 标成已可用。
- 不默认以音乐、玻璃效果或复杂动画代表质量；优先清楚、可读、可操作。

## 3. 首批 A1：状态方案与独立原型

### A1.1 先落一页范围说明

在 `plan/ui/design-spec.md` 明确：
1. 页面主要区域和信息层级。
2. 输入、任务、播放器三种状态如何关联。
3. 本轮做什么、不做什么。
4. 需要工程提供哪些状态/字段。

有影响核心目标的分歧再问用户，最多 1—3 个问题；否则沿用现有基本视觉体系做一个明确方案，不要求用户先选择大量风格。

### A1.2 必须覆盖的状态

- 空白输入与可用示例。
- URL 和直接文本的明确来源选择；切换来源不能继续提交隐藏旧正文。
- 正文解析成功：标题、字数、来源及内容预览；截断/获取不完整时有持久提示。
- 生成中：解析、剧本、配音、拼接四阶段；未知进度只显示阶段与耗时。
- 配音阶段：已完成 N/M、重试中、已复用缓存数（只在接口实际提供时展示）。
- 失败：卡在哪一阶段、错误原因、可执行动作；不把所有失败都写成“再点一次”。
- 恢复：返回现有任务、继续未完成部分；刷新后的“正在恢复任务信息”。
- 就绪：明确播放按钮、时长、字幕跳转、来源入口。
- 播放错误/文件失效：保留任务信息，提示修复动作，不假装正在播放。
- 最近任务：用于找回作品的最简入口，不做复杂内容管理。

未来功能可在设计说明中记录，但不要在首屏放大量不可用按钮。原型中的恢复/缓存等尚未上线能力，须显式标为模拟演示。

### A1.3 原型要求

- 独立入口 `design/web-mvp/index.html`，资源限同目录，优先原生 HTML/CSS/JS，无需新增应用依赖。
- 使用固定 mock 数据演示正常、失败和恢复三条路径，不发送真实文章、Key，不调用生成接口，不产生费用。
- 不自动播放声音；播放演示使用清楚标注的模拟状态或合法本地样本。
- UI 不保存新一份业务真相：正式实现中任务进度来自后端、可播放时长来自有效音频，原型中对应字段有说明。
- 不绘制“混音完成”作为必经阶段；当前只有音频拼接，没有真实混音。
- 使用受管浏览器预览前读取对应 browser Skill，并用结构检查和截图验证布局；若预览受阻，如实记录。

## 4. 与工程的接口交接

B 负责维护 `plan/engineering/api-contract.md`。文档未出现时可以先基于具名 mock 字段做原型，并列出映射需求，不能自行宣布接口已实现。

建议表达的信息（字段名待工程确认）：jobId、status、stage、stageStartedAt、completedSegments、totalSegments、retryAttempt、cacheHits、可恢复错误、允许的操作、result。

`status` 与 `stage` 分离：例如“失败”是状态，“语音合成”是发生错误的阶段。取消按钮只有在后端确实停止工作后才能显示“已取消”；原型模拟需注明。

交接材料要说明：
- 各 UI 区块和交互如何映射现有能力。
- 哪些是已实现、待工程支持、未来候选。
- 标明迁移时可保持的 DOM ID/事件边界；由 A 保留现有业务保护，不整份替换 app.js。
- 原型是一份设计产物；批准后由 A 接入生产前端，B 提供真实接口，不负责 UI 集成。

## 5. A1 验收与停止点

交付：
1. `plan/ui/design-spec.md`：流程、状态表、交互规范、范围。
2. `design/web-mvp/index.html` 及必要资源：可交互原型。
3. `plan/ui/handoff.md`：预览方法、验证结果、字段依赖、截图位置、未解决问题。

自检：
- 用户在任何状态都能回答“当前在做什么、出了什么问题、接下来能做什么”。
- URL/正文的当前来源清晰，重复点击不会在演示中创造多个模糊任务。
- 键盘可操作、输入有标签、焦点可见、错误不只依赖颜色。
- 原型假数据与真实接口状态明确区分。
- 没有更改任何生产代码或依赖。

完成后展示原型与交接摘要，等待用户确认设计；不要自动进入集成，也不要继续扩展移动端、账号体系或商业 TTS 功能。
