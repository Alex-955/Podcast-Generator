## 1. 已修复项

### B-F1 握手超时/取消导致进程退出（优先）

文件：`src/services/edgeTtsAdapter.js`

根因：`teardownResources()` 在 `ws.terminate()` 之前 `ws.removeAllListeners()`。CONNECTING 状态下 `terminate()` 会异步发出 `'error'`（"WebSocket was closed before the connection was established"）；此时监听器已被移除，该事件升级为未捕获异常导致整个进程退出（exit 1）。try/catch 无法捕获异步 emit。

修法（不使用全局 uncaughtException 兜底）：

- 资源清理幂等：`tornDown` 标记，重复清理安全；
- **不再移除 ws 监听器**：连接级监听保留到连接真正结束，迟到事件走 `fail()` 幂等路径被安全忽略；
- `settled` 仅在真正 resolve/reject 时置位；新增 `finalizing` 区分 `turn.end` 之后的 flush/publish 阶段；`ws.on('error'/'close')` 在 `finalizing || settled` 后视为正常收尾直接忽略，其余时刻必须 settle——close/取消/超时幂等且 Promise 不悬挂；
- 统一 settle 入口 `settleResolve`/`settleReject`（`fail = settleReject`）：flush/publish 阶段异常同样走 settleReject，不吞错、不悬挂（含 `fs.renameSync` 发布失败路径）；
- `stream.end()` 回调先查 `settled`：发布前已被取消/失败（与异步清理的竞态）时只清理，绝不发布；
- 发布前产物完整性校验（与 B-F2 联动）+ `fs.renameSync` 原子发布；
- 附带：`mkdirSync` 失败由同步抛错改为 `Promise.reject`。

### B-F2 残缺 MP3 被当有效产物发布（优先）

文件：`src/services/mp3Utils.js` + `edgeTtsAdapter.complete()` 发布卡点

根因：旧 `getMp3DurationSeconds` 解析到帧头即累加采样数，不校验整帧是否在 buffer 内——5 字节残片被判有效且报 0.024s，随后作为产物发布。

修法：

- 新增 `analyzeMp3(buffer)` 严格完整性分析，reason：`too-short` / `no-frame` / `frame-sequence` / `truncated-tail` / `mixed-format`；
- 完整帧边界 `offset + frameLength ≤ body.length`，截断尾帧一律拒绝（`truncated-tail`）；帧序列一致性校验 versionBits / sampleRate / samplesPerFrame（`frame-sequence` / `mixed-format`）；容忍 ID3v2 头与 ID3v1 尾（'TAG' 128 字节），其外的尾部垃圾拒绝；
- `isValidMp3 = analyzeMp3(buffer).ok`；`getMp3DurationSeconds` 不 ok 返回 0（不再虚报时长）；
- 发布卡点：`complete()` 中 `isValidMp3` 不通过抛 `TtsUpstreamError('protocol', '合成产物不是完整有效的 MP3（帧不完整或格式不一致）')`，产物绝不发布，临时文件清理不留残骸。

### B-F3 SSRF 校验补强

文件：`src/services/extractor.js`

- 新增 IPv6 规范化：`expandIpv6`（去 `%zone`、内嵌 IPv4 转 hex 组、展开 `::`）、`mappedIpv4`（`::ffff:x` 与旧式 `::x` 映射回点分四段）、`isBlockedIpv4`；
- `assertSafeFetchTarget` 重写：IPv6 字面量先规范化再判定；IPv4-mapped/旧式映射地址走 IPv4 规则（0/10/127/172.16–31/192.168/169.254/≥224 拒绝）；原生 v6 拒 `::`、`::1`、`fc00::/7`、`fe80::/10`；解析不了的 IPv6 字面量按危险处理。修复复现漏洞：`http://[::ffff:127.0.0.1]/` 曾被误接受；
- `defaultFetcher` 手动逐跳重定向循环：`maxRedirects:0` + 自循环，每跳 `assertSafeFetchTarget`，上限 5 跳（第 6 个响应仍是 3xx 抛「重定向次数过多」），缺 `Location` 抛错；`{ request }` 可注入供离线测试；保留 20s 超时 / 5MB 上限；
- **明确未做**：DNS 解析后复检（DNS rebinding 防护）。不宣称完整 SSRF 防护。
