# 播客生成器：现状检查与下一步分工

检查日期：2026-09-26（GMT+8）  
依据：当前磁盘代码、UI/后端报告、两个指定历史会话的最近记录，以及本轮离线测试。本文是协调与建议，不是启动全部后续功能的授权。

- **生产前端**：仍为 `public/` 的现有页面；新设计未接入。
- **新 UI**：`design/web-mvp/` 为独立 Mock 原型。最新 handoff 为 A1 收尾版，启动报错已消除，正文预览、阶段进度与输入修改后的失效处理已有改进。真实 API、持久化恢复尚未接入。
- **后端**：TTS 生命周期、残缺 MP3 检查、抓取重试/重定向与部分输入校验已有回归证据。后续 LLM/抓取超时改动未收尾，不能宣布 B0.1 整体通过。
- **报告与代码不同步**：B0.1 报告状态截至 9 月 22 日 14:23，当前源码与新增 `llmDeadline` 测试有该日 15:03 的修改；报告没有覆盖最终磁盘状态。主要被检查文件未见 9 月 22 日之后的修改，不据此推断会话是否实时运行。
- **B1**：持久化任务、真实进度查询、恢复、句子缓存尚未实现。API 文档中的 SSE 等只是旧草案，不作为已批准任务。

## 2. 本轮验证结果

### 2.1 后端：局部通过，全量未通过

为避免再次长时间等待，本轮执行：

```bash
npm test -- --test-timeout=15000
```

输出：81 项记录，77 pass、1 fail、3 cancelled，总耗时约 15 秒；统计包含被测试发现机制载入的辅助文件，不能理解为 81 个独立业务断言。

关键通过项包括：
- TTS 握手挂起超时、握手期间取消，子进程正常退出；
- 发布失败能明确拒绝；
- 5 字节 MP3 残片及截断音频拒绝发布；
- IPv4-mapped IPv6 与逐跳重定向检查；
- 已有输入来源、对白清洗、MP3 时间轴测试。

未通过/未完成：
1. `test/llmDeadline.test.js`：声称子进程应在 2.5 秒内自然退出，实测约 8.1 秒，断言失败。该测试目前把调用本身耗时和调用结束后的句柄残留合并计时，尚不能据此单独证明根因是定时器泄漏。
2. 同文件假传输超时测试：`Promise resolution is still pending but the event loop has already resolved`；随后一个用例也被取消。需要分清 unref 定时器与测试事件循环的关系，不能直接当成三个独立业务故障。
3. `test/routes.test.js`：输出到缺 API Key 用例后，在本轮人为设置的 15 秒上限被取消。结论是“有界回归未通过”，不是已经证明它永远不能结束。

不建议继续增加更多功能来解决这些测试。应分别测量请求拒绝时间与进程自然退出时间，检查本地测试端点、传输/代理环境及定时器生命周期；不要直接增大超时或降低断言标准。

### 2.2 UI：可加载，仍有两个输入状态缺口

本轮独立验证：
- Node 加载原型成功，导出 10 个入口；原先 `initPrototype` 的 ReferenceError 未再出现。
- 受管浏览器可打开原型并读到页面结构、模拟标记、播放器、历史与输入控件。
- 本轮截图工具返回“尚未完成可捕获布局”，所以未完成像素级视觉与窄窗口验收，也不替用户批准样式。

通过离线 DOM 桩和假时钟补测，仍复现：
1. 开始解析正文 A → 在 400ms 模拟解析完成前改成 B → 旧回调仍显示 A 的确认卡。`handleInputChange` 会清草稿，但解析回调只比 currentRunId，没有比输入版本。
2. 解析确认后切到 URL 页，`switchInputTab` 没有让草稿失效，旧确认卡仍显示。

这是对“解析完成后再改正文”路径之外的补充检查，不否定已完成的样式与其他修复。下一批只补这两个输入边界，避免又要求整套设计重做。正式接入优先保留生产 `public/inputSource.js` 的保护，不将 Mock 状态机整份搬入生产。

## 4. 推荐方向：先形成真实可用的一版，再解决等待与复用

### 第一批：前端定样式，后端收尾，可并行

**A：样式定稿**
- 以现有原型为基础，不重新生成另一套完整系统。
- 重点让 Alex 审阅正常输入、生成中、成功播放、失败提示四种视觉状态：布局、配色、字号、间距、表单、按钮、播放器与字幕。
- 上述两个输入失效问题做小修即可。候选功能明确禁用；不把导出、混音、动态频谱纳入本批验收。
- 后端没有返回的状态可以留在 Mock 演示里，但不得表现为正式能力。未来恢复/缓存状态不应阻塞这次样式确认。
- **停止点**：交付可预览页面、变更摘要与未接接口清单，等待样式确认，不自动覆盖生产前端。

**B：超时与契约收尾**
- 只处理 `llmDeadline` 失败、路由测试耗时，以及对应的最小业务/测试修复。
- 更新 B0.1 报告与 `api-contract.md`。仍需修正文档中 `/api/voices` 与 `/api/bgm-list` 响应层级、“严格交替”等过时描述。
- 给出可重复的离线回归命令、总耗时和未验证项；若未定位，提交证据和阻塞，不继续展开不相关重构。
- **停止点**：回归与文档交付；不开始 B1，不改 `public/`。

### 第二批：新界面接现有后端，交付一条完整路径

前提：样式得到用户确认、后端最小基线通过、接口契约一致。

由 A 接入当前接口，B 支持后端问题。验收“粘贴正文 → 解析确认 → 生成 → 实际音频播放 → 字幕跳转”，再覆盖 URL 抓取失败后的正文回退。

当前同步接口不能提供的细粒度配音进度，正式页面使用诚实的等待状态，不能照搬 Mock 的句子计数、取消、断点恢复。接口缺口列入下一批，不为接样式同时重写任务系统。

先跑离线/mock 联调与已有授权音频的播放检查；真实 LLM/TTS、付费调用或正文外发需确认测试输入和调用边界。本轮未执行完整真实生成与听感验收。

### 第三批：B1 最小任务能力，再扩恢复与缓存

目标是解决用户实际痛点：不知道卡在哪、失败重复等待、刷新找不到结果。

建议分两次验收，而不是一次做完：
1. **B1a**：稳定任务 ID、持久化阶段/结果、状态查询、刷新后找回同一任务；前端轮询真实阶段与已完成片段数。
2. **B1b**：明确的取消/失败恢复语义、复用已完成片段、句子缓存和最近任务入口。缓存键包含实际生效的 Provider、模型/版本、声音及合成参数；不持久化凭据。

SSE 可选，首版轮询即可。B1a 应预留中间产物字段以支撑 B1b，但不必一开始做复杂调度系统。

### 随后：内容与听感

稳定闭环之后，用同一段公开或用户授权文本比较现有 TTS 与商业候选；先试听、比较价格，再决定供应商。忠实原文、自然听感优先于背景音乐/动效。

移动端、跨设备、分享、导出、复杂混音及自动删除历史作品继续后置；不换前端框架，不默认增加 Redis 或微服务。

## 5. 安全和验收边界

当前仍有关闭 TLS 校验、开放 CORS、未限定回环监听；SSRF 未完成 DNS 后验。不能据此宣称公网可用，也不能忽略这些配置。

建议在准备正式联调/持续使用前，单独取得 Alex 对恢复 TLS、默认回环监听和同源策略的确认；涉及代理/证书的环境兼容要先说明。本文不替用户批准或执行这些变更。

本轮仅更新协调文档与分工记录，没有修改业务代码、替其他会话下发指令，或启动 B1。
