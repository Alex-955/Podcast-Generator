# A1 UI 交付评审：保留原型方向，返修后再验收

日期：2026-09-22（GMT+8）  
评审角色：协调会话；未修改原交付物或生产代码。  
评审对象：`plan/ui/handoff.md`、`plan/ui/design-spec.md`、`design/web-mvp/`。  
验收依据：`plan/ui-design-brief-2026-09-22.md` 与共享路线图。

## 结论

当前可以作为交互草稿继续迭代，但不建议批准 A1 完成，也不建议进入生产集成。无需推倒重做：保留输入/播放器分区、阶段卡片、原位错误提示和明显的 Mock 标识，先修正交互语义与交接依据。

原型允许使用模拟数据，不要求 A 实现后端；但模拟应当正确表达目标交互，不能把失败回退变成凭空生成正文，也不能以标题切换冒充历史恢复。

## 本轮验证边界

- 已读取全部四个原型文件、设计规范、交接文档和原任务书。
- 已用受管浏览器复现反爬回退、TTS 失败后恢复、历史任务切换。
- 使用离线 VM 和假时钟确认正常流水线能到达完成回调，复现旧场景回调污染新场景；这不是浏览器真实时序验收。
- 正常流程浏览器等待未在设定时间内收敛，原因未定位，不能仅由此认定业务 Bug。
- 两次截图调用均返回 `Current display surface not available for capture`，本轮没有完成视觉截图验收，不能独立背书原报告的截图结论。
- 工程目录在本次检查时只有 `b0-plan.md`，尚无 `api-contract.md`；不能声称设计接口已与工程契约对齐。
- 没有完整版本差异基线，不能独立证明 UI 会话“从未改过任何生产文件”；本次检查的原型交付文件位于约定目录。

## 必须修正的事项

### R1：反爬失败后的回退必须保留事实边界

证据：`prototype.js:185` 的 `handleFallbackAction` 自动写入 `MOCK_DATA.antiSpiderError.fallbackText`，接着调用 `handleParseArticle(true)`，直接显示“正文解析已完成”。该函数始终使用 happyArticle 的摘要、字数和时长。

浏览器实测：自动填入 66 字符的样本文本，确认卡却显示约 3840 字和另一份文章摘要。

修正：
- 主动作改为“切换到正文粘贴”，聚焦输入框；保留用户已输入的正文，没有则留空。
- 若需要演示样本，单列“填入示例正文（模拟）”，不能暗示失败后自动获取到了原文。
- 确认卡内容由当前输入对应的 fixture/状态产生；不能把任意文本都标成同一篇成功解析结果。
- 空输入、正文不完整、截断要有明确状态。

验收：抓取失败时未提供正文不能进入“已解析”；已有用户文本不被覆盖；字数、标题、来源与当前输入一致。

### R2：交接文档不能替工程单方面确定接口与架构

`handoff.md` 固定了 `/api/extract`、`GET /api/stream-generate`、`/api/retry-step`、`/api/audio/:id` 以及 SSE，并写“后端接口须满足”。当前未有已对齐的工程契约。

文档列出的 `#btn-parse`、`#btn-confirm-start`、`#step-1`、`#step-4`、`#error-banner`、`#audioPlayer`、`#dialogueList` 均不存在于实际原型 HTML；实际播放器是计时模拟器，不是 HTML5 Audio。

修正：
- 改为“UI 需要的信息/动作”和“候选字段，待 B 确认”，不指定必须用 SSE；轮询也应能驱动相同界面。
- 列出真实 DOM ID 与字段映射，区分原型显示模型、现有接口和候选任务接口。
- `status` 与 `stage` 分开，允许操作由任务状态决定。
- 连接超时/挂起与限流分开；不能因超时就标 `ERR_TTS_RATE_LIMIT`。
- 明确 failedIndex 是零基索引还是自然序号；当前 mock 写 4、界面称第 4 句，而交接公式又加 1，需统一。
- 删掉“完全对齐”“100% 吻合”等无逐项证据的表述，写实际测试结果与未完成项。

### R3：历史载入与播放状态必须一致

证据：`prototype.js:369` 的历史点击只改标题，然后触发 happy 场景；播放器、字幕和播放总时长始终来自 happyArticle/硬编码 48 秒。

浏览器实测：点击标记 03:12 的第二条历史记录，播放器标题改变，但时长仍为 00:48，字幕仍讲第一篇文章，并出现第一篇文章的解析确认。

其他状态问题：TTS 恢复完成后进度提示已就绪，播放器仍显示“暂停中”；初始化时虽然“等待生成”，播放按钮与样本字幕已经可操作。

修正：
- 每条 mock 历史任务有一致的标题、字幕、时长和就绪状态；点击只载入该任务，不重新进入解析/生成。
- 没有可播放结果时禁用播放；若初始展示样本，单独标成“示例播放器”，不能与当前任务混淆。
- 正常完成与恢复完成统一进入就绪态。
- 补足刷新恢复、播放失败/音频失效的可演示状态；无需接真实服务。

### R4：模拟任务也需要防止状态串线

证据：各 `setTimeout`/TTS interval 没有统一取消或运行标识。切换场景只停止播放计时器，没有停止生成回调。离线假时钟复现：启动反爬场景后立即切正常场景，旧回调仍将新界面的错误框设为可见。

另外，`switchInputTab` 只切显隐；没有使已有解析确认失效。改变输入也没有来源绑定或过期结果保护。

修正：
- 用单一 mock 状态模型和运行 ID 驱动界面，切场景/换任务时清理所有旧计时器或忽略过期回调。
- 解析结果绑定输入来源；修改 URL/正文后明确要求重新确认。
- 运行中禁止重复启动，或提供清楚的取消/替换行为。

验收：快速切场景、修改来源、连续点击都不会出现上一任务的错误、完成提示或字幕。

### R5：收回未批准能力，不把未知进度伪装成百分比

原设计规范把轻音乐混音作为 merge 阶段，原型列出“带语音避让”、Lo-Fi 和多种对话风格；这些不是当前已实现或本轮已批准的必做能力。

阶段百分比按固定 15/25/50/65 等值推进，设计规范也给出固定区间。顶部的 Mock 标识说明数据是假的，但不能替代正式产品的进度语义设计。

修正：
- 合并阶段统一叫“音频拼接/校验”，移除混音和语音避让承诺。
- 风格和额外 BGM 先从主流程移除或明确列为未来候选；导出保留为已有次级能力，不扩展为当前重点。
- 非可量化阶段显示阶段与耗时；TTS 显示完成 N/M，未知总量不显示伪精确总百分比。
- 原型需演示“长时间无进展/重试中”，不只是快速走完预设动画。

### R6：补全任务书中的关键状态和可访问性

目前缺少完整的空白/无效输入、正文预览与截断提示、刷新后恢复、播放错误状态。文档写有取消按钮，但原型没有对应实现；最近任务与字幕使用只有 onclick 的 div，不能正常通过键盘聚焦触发。输入依赖 placeholder，部分 label 未绑定控件。

修正：
- 用具名 mock 状态补齐上述关键状态，不要求做真实缓存或音频服务。
- 历史项/字幕使用按钮或提供完整键盘语义；表单控件提供关联标签，播放按钮有可理解名称。
- CSS 当前没有响应式断点，需要验证窄桌面/侧栏窗口，必要时双栏改为单栏；不要求开发手机端产品。
- 所有声称已验证的项提供复现步骤；截图若存在给出路径，没有就如实写未验证。

## 建议执行方式

A 继续做 **A1 返修**，只改 `design/` 和 `plan/ui/`；不要进入其交接文档提出的 A2 后端/SSE 改造。修复后更新 `handoff.md`，逐条列出 R1—R6 的完成证据与未完成项。

B 继续原定 B0，不受此次 UI 返修阻塞。B 的候选接口交付后，A 再做映射确认；任务、进度、恢复与 UI 正式集成按路线图的 B1 范围另行启动。

设计风格由用户审阅决定；本报告主要验收交互语义、范围和交接准确性，不因个人审美要求推倒重做。
