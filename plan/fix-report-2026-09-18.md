# AI 妙听播客生成器 — 修复与分析报告

> 时间：2026-09-18 09:40 – 11:12 (GMT+8)
> 范围：P0 正确性修复、微信文章抓取修复、生成链路超时问题诊断与修复、架构分析
> 状态：所有修复已生效并通过实测，服务运行于 http://localhost:3000

---

## 一、项目当前形态

- 技术栈：Node.js + Express 后端（`server.js` + `src/services/*`），原生 JS 前端（`public/`）。
- 核心链路：抓取文章（微信公众号/通用网页）→ LLM 重构双人剧本（DeepSeek 等 OpenAI 兼容接口）→ Edge-TTS 逐句合成 → 纯 Node 拼接 MP3 → 网页播放器（字幕同步高亮）。
- 依赖特点：全程无 ffmpeg、无付费 TTS Key。Edge-TTS 为微软非官方逆向接口。

## 二、已修复问题

### 2.1 P0 正确性修复（4 项）

| 问题 | 根因 | 修复 |
|------|------|------|
| 字幕高亮随播放持续漂移（每句漂 0.35s，20 句漂 7s） | 时间轴按句间 0.35s 停顿累加，但拼接时从未真正插入静音 | 新增 `src/services/mp3Utils.js`：解析 MP3 帧头、生成与源音频格式一致的静音帧；`audioMerger.js` 拼接时插入真实静音帧 |
| MP3 时长按固定 48kbps 估算，码率不符时进度/字幕全错 | 用文件大小 ÷ 假定码率 | `mp3Utils.getMp3DurationSeconds` 逐帧精确累加，解析失败才回退估算 |
| 前端所有提示看不到 | `app.js` 中第二个 `showToast`（仅 console.log）按 hoisting 覆盖了完整实现 | 删除重复定义 |
| LLM 输出角色名多变导致错乱 | speaker 未归一化，前端靠 `includes('泽')` 猜测 | `scriptEngine.normalizeDialogue`：强制收敛为阿泽/小晓，过滤空台词，未知角色按序交替兜底 |

实测：3 句合成 → 合并 → 字幕时间轴与实际音频误差 0.03s。

### 2.2 微信文章抓取（"不报错但扒不下来"）

根因（两个叠加）：
1. **静默失败**：URL 无效或微信返回反爬/已删除页时，extractor 返回 `success:true` + 空内容，服务端不校验直接透传。
2. **输入误用**：正文粘进链接框时，拿正文当 URL 请求，报难懂的 `Invalid URL`。

修复（`extractor.js` 重写 + 前后端校验）：
- 错误契约改为"失败必 throw，文案用户可理解"。
- 微信错误页特征识别（环境异常/操作频繁/被删除/违规/链接失效/参数错误），各自给出针对性提示 + "可直接粘贴正文"退路。
- 双 UA 策略（微信移动 UA → 桌面 UA 重试），标题提取增加 og:title 等回退。
- 正文有效性下限 200 字，达不到才判失败。
- 前端发请求前拦截非 http 开头的链接输入，提示切到"直接贴文字"。
- 超过 1.2 万字返回 `truncated` 标记，前端提示"已截取前 1.2 万字"。

实测：真实微信文章（8933 字）抓取成功；四种异常输入均返回明确中文指引。

### 2.3 "一键生成把链接当正文"（LLM 生成自嘲剧本的彩蛋）

根因：前端"一键生成/仅生成剧本"**从不把 URL 传给后端**，文本框为空时把 URL 字符串当作"文章内容"发给 LLM。

修复：
- 前端：有链接且无正文时传 `url` 由后端抓取；`/api/generate-script` 后端也支持 `url` 入参。
- 后端保险：传入"正文"若本身是链接（`^https?://\S+$`），直接报错指引。

### 2.4 背景音乐从不播放

根因：`setupBgm()` 在主音频尚未开始播放时检查 `mainAudio.paused` 决定是否启动 BGM，条件永远不成立。

修复：BGM 跟随主音频 play/pause 事件自动启停；选择"纯净人声"则完全关闭；换选 BGM 时若正在播放立即生效。

### 2.5 生成链路超时（三轮递进诊断）

| 现象 | 根因 | 修复 |
|------|------|------|
| 报错 `timed out`（第一轮） | LLM 调用 axios 超时 60s，长文 + 完整 JSON 输出不够用 | 放宽到 180s，超时文案给出退路 |
| 报错 `Timed out`，网页端无任何提示（第二轮） | ① `node-edge-tts` 抛**字符串** `'Timed out'` 而非 Error，`error.message` 为 undefined，接口 error 字段为空；② 前端 catch 只弹 3.5s toast | TTS 错误规范化；前端错误持久显示在状态栏 |
| 重试 3 次仍 `Timed out`（第三轮） | 见下文"根因分析" | 快速失败 + 多次重试（见 2.6） |

### 2.6 Edge-TTS 连接黑洞 — 根因分析与关键修复

**实测数据**（模拟服务端行为，连续合成 8 句）：
- 6 句约 2s 完成；2 句 WebSocket 连接挂起等满超时无响应（挂起率约 20~25%）。
- 挂起的句子重试一次即成功。
- 历史包袱：库默认 timeout 仅 10s，长句合成需 14s+，必超时；放宽到 60s 后，挂起连接又浪费 60s。

**根因分层**：
1. Edge-TTS 是非官方逆向接口（无 SLA），`speech.platform.bing.com` 的 wss 长连接在本机网络路径（存在代理/中间设备，曾有 TLS 证书链错误佐证）下约 1/4 概率被黑洞。环境问题，非配置错误。
2. 架构放大故障：同步单请求串行 20 次 WS 连接，任一句挂起整单失败；单句失败率 25% 时 20 句全过概率 <1%。
3. 参数策略反向：正常连接 2s 内出音频，挂起连接等再久无用。"一次等很久"（60s）应改为"快速失败 + 立即重试"。

**修复**：单次尝试超时 10s，最多 6 次重试，间隔 300ms。单句残余失败率 ≈ 0.25^6 ≈ 0.02%。实测 8 句连续合成 14.1s 全部成功（修复前同场景 2 分多钟且可能失败）。

### 2.7 文章结构化提取

原实现把全文压成一行（`\s+` → 空格），丢失段落/标题/列表结构，影响 LLM 对文章脉络的把握。已改为保留块级结构（段落/标题/列表换行），段内空白折叠。实测微信文章输出为清晰分段形态。

### 2.8 其他

- 默认模型名 `deepseek-chat` → `deepseek-flash`（server 兜底、前端默认、设置弹窗三处）。注意：浏览器 localStorage 中的旧值会覆盖默认值，需在设置里确认。
- `NODE_TLS_REJECT_UNAUTHORIZED='0'` 从 ttsService 移到 server.js 入口并注释：本机证书链（代理/自签 CA）导致 Edge-TTS 的 TLS 连接失败，该库无法注入定制 agent，故需全局关闭；**仅限本地使用，公网部署前必须移除**。

## 三、架构分析结论（与 OPPO AI 妙听对比）

- **OPPO 的流式架构**（生成一段即开播、后台继续合成）体验上限更好：首句延迟从分钟级降到秒级。本质是"合成速度 ≥ 播放速度"的流水线。
- **OPPO 断供问题**（听到后面加载不出来）与我们同根：上游 TTS 抖动 + 预取缓冲不够深 + 缺少失败重试/断点续播。不是"技术做不到"，而是流式 + 不可靠上游需要深缓冲、并发预取、失败重试、断点续播等成套工程。
- **结论**：我们近期不追流式；先用"重试对冲 + 句子缓存 + 进度可见"把同步全流程做稳，流式作为下一阶段。

- Edge-TTS 为非官方接口，微软随时可能限流或改协议；已用重试对冲，但需留意突然全挂的情况（届时考虑接入付费 TTS Provider，代码已预留 voiceMapping 结构便于扩展）。
